# Plague IT: architecture and data schemas

This is the map of the code as of Phase 5. The README covers running, testing, adding
content, the balance knobs and deploying.

## Running it

```sh
npm install
npm run serve          # python3 -m http.server 8000, then open http://localhost:8000/dev.html
npm run lint
npm run build          # writes index.html (not committed)
npm test               # Node tests, then browser tests against dev.html, index.html, and index.html from disk
npm test -- node       # Node tests only (no browser)
npm test -- sim        # only tests whose file or name contains "sim"
```

Add `?seed=anything` to the URL to replay the same game.

## Modules

```
data/                 all content and numbers (plain JS modules, bundled by the build)
  index.js            DATA: the one object the engine reads everything through (builds sites from geo + sites.js)
  geo.js              GENERATED by tools/build-geo.mjs: state/province outlines, borders, lakes, top 500 metros
src/
  sim/                the simulation: pure functions over plain JSON state, no DOM
    rng.js            seeded RNG (mulberry32); its whole state is state.rng
    world.js          static lookups derived once from DATA (site index, susceptibility, links)
    state.js          createState(): a fresh game
    stats.js          Spread / Noise / Impact = strain base + owned evolutions
    sim.js            step() = one fixed tick; startInfection(), collectBubble(), evolve(), devolve()
    defense.js        the SecOps AI: funding, alert, picking responses, what they add up to (state.dfx)
    bot.js            autopilot that plays whole games headlessly (balance tests)
  news.js             picks news ticker headlines for events and as filler (pure)
  game.js             fixed-timestep driver: real time × speed → whole ticks; pause, 1×/2×/3×
  render/             canvas only, reads state, never writes it
    geo.js            lon/lat → map units (Albers equal-area conic, Hawaii as an inset), point-in-polygon
    camera.js         pan/zoom limits, screen ↔ map conversion
    map.js            draws state/province fills, lakes, metro dots, links, bubbles and effects; hit-tests regions
  input/pointer.js    Pointer Events: drag to pan, pinch and wheel to zoom, tap
  ui/                 DOM: top and bottom bars, news ticker, title/stats/settings (menus.js), setup,
                      site panel, evolution screen, end screen + timeline graph, debug panel
  audio.js            synthesized sound effects (Web Audio), created after the first tap, silent when muted
  score.js            scoreGame() and the summary best scores and stats keep (pure)
  storage.js          localStorage wrapper ("plagueIT:" prefix, try/catch everywhere)
  save.js             what's saved (settings, profile, best scores, stats) and how loaded data is cleaned
  validate.js         checks data/ for mistakes; run by the data tests
  main.js             wires everything together and runs the frame loop
```

Rules that keep it testable:

- **The simulation never touches the DOM, canvas, clock or Math.random.** It runs the same
  in the browser, in Node tests and in headless balance runs.
- **The state is plain JSON.** `JSON.parse(JSON.stringify(state))` resumes identically,
  which is how saves will work and what the determinism tests check.
- **One tick = one in-game hour.** At 1× there are `BALANCE.ticksPerSecond` ticks per
  real second. Rendering runs at screen rate; frame rate never changes the outcome.
- **Player actions are functions applied between ticks** (startInfection, collectBubble,
  and in Phase 2 evolve/devolve), so a game is reproducible from its seed plus its actions.
- **Events** (siteReached, bubbleSpawned, bubbleCollected) are queued on the state and
  drained by the UI each frame for effects and, later, sound and the news ticker.

## The map

The map is the USA and Canada. Each **site** is a state, DC, province or territory (64 in all),
plus one air-gapped facility. `tools/build-geo.mjs` downloads Natural Earth public-domain data
(admin-1 at 1:50m, populated places, lakes), simplifies the outlines, finds shared borders,
and picks the **top 500 metros** by population (anything within 30 km of a bigger metro is
folded into it). It writes `data/geo.js`; rerun it with `node tools/build-geo.mjs`.

- A region's endpoints = its metros' population / `balance.map.peoplePerDevice` (1 per 1000
  people), at least `minDevices`. Its connectivity rises with the log of its population.
- Shared borders are always-open `border` links, so infection creeps overland as well as
  jumping along the WAN/VPN/cloud/email links in `data/links.js`.
- When a region is first reached, the entry metro is picked weighted by population; the
  metro dots then redden outward from it as the region's infection grows.
- Regions carry **tags** (finance, government, energy…) that nudge their traits and that
  some evolutions boost spread in (`tagSpread`).

## How spread works

Each site holds counts: `healthy`, `infected`, `remediated` (and `devices`, the total).

- **Inside a site** (logistic growth), per tick:
  `new = within × Spread × strain.withinSite × susceptibility × infected × healthy / devices`,
  rounded randomly so the average is right.
- **susceptibility** = `(1 − patch × 0.55) × (1 − savvy × 0.45) × (1 − maturity × 0.35)`
  (weights in `BALANCE.spread.traitWeights`).
- **Between sites**, per open link and direction, per tick, the chance to seed one machine is
  `between × Spread × strain.betweenSites × linkWeight × (infected / devices at the source)
   × target connectivity × target susceptibility`.
- A link with `requires` only carries infection once that evolution is owned. Air-gapped
  sites only connect over `airgap` links, which need Air-Gap Hopping.
- **Bubbles**: one always appears when a site is first reached; otherwise each tick a site
  with new infections has a `newInfections × perInfectionChance` chance to drop one. They
  expire after `ttl` ticks, with at most `maxOnMap` at once.

## Evolution, detection and remediation (Phase 2)

- **Buying**: price = `cost × (1 + evolve.costGrowth × owned in that branch) × strain.evolveCost`.
  All prerequisites must be owned. **Devolving** refunds `evolve.refundRate` of what you paid
  and is blocked while an owned evolution needs it. The game pauses while the evolution
  screen is open.
- **Effects** add up across owned evolutions: the three stats, `tagSpread`,
  `remediationResist`, `cleanResist`, `reinfect`, `pointsPerDay`, `jump` (caps in `balance.caps`).
  Spread has diminishing returns (`Spread ^ spread.power`).
- **Detection**: each tick, hidden suspicion grows by
  `detection.rate × (Noise + Impact × impactWeight) ^ power × √(share infected) × difficulty.detection`.
  At `detection.threshold` SecOps notices, the Remediation bar appears, and you get a bubble.
- **Remediation**: the bar fills by `remediation.rate × (1 + Impact × impactBoost) × difficulty
  × strain × (1 − remediationResist)` per tick. Machines are cleaned in proportion to the
  site's working machines, so **a fully compromised site can't be cleaned**. Cleaned machines
  can be retaken at `reinfectFactor` of a healthy machine's rate.
- **Win**: every endpoint infected (including the air-gapped factory, so you need Air-Gap
  Hopping). **Lose**: the bar reaches 100%, or the last infected machine is cleaned.
- **Balance tests** play 8 seeds per strain and difficulty with the autopilot: the `smart`
  plan must win at least once, and the `idle` and `reckless` plans must lose. Current
  results for the Worm: smart wins about 7/8 on Understaffed and Normal, about 4/8 on
  Competent SecOps.

## Defenders: the SecOps AI (Phase 3)

Everything here starts the tick SecOps detects you (`src/sim/defense.js`, numbers in
`BALANCE.defense`, responses in `data/responses.js`).

- **Funding** per tick = `fundingPerDay / 24 × (1 + impact × impactFunding + share infected
  × shareFunding) × difficulty.funding`. Impact is what gets budgets approved.
- **Alert** (0..1) = `days since detection × alertPerDay + share infected × alertShare`.
  Each response has a `minAlert`, so the big ones (isolating a site, reimaging) come later.
- **Decisions** every `decisionEvery × difficulty.aiInterval` hours. The AI weighs every
  available response: `weight + (matching triggers) × difficulty.smarts`, where triggers
  are evolutions you own (Email Attachments makes Block Email Attachments likely) and your
  stats. It picks at random by weight; if it can't afford the pick it **saves up** for it.
  Global responses happen once; site ones hit the most infected site (up to `maxUses`).
- **Effects** (recomputed into `state.dfx` every tick): closed links, blocked evolutions
  (their spread bonuses stop; their noise stays), hardened site traits, slower spread inside
  a site, faster remediation, and instant cleaning (reimage). Isolation lifts after 10 days.
- **Counters**: each response lists `counteredBy` evolutions. Owning one halves the
  response (`counterFactor`), even if you buy it after the response landed. The toast
  names the counter, and the evolution screen shows what each node blocks or counters.
- **Incident response firm**: once total funding passes `irFirm.funding`, remediation and
  cleaning speed up for the rest of the game.

The news ticker (`src/ui/ticker.js`) shows a headline for events (`data/headlines.js`
`when.event`), SecOps moves (each response's `headline`, which cuts in as breaking news),
and, when nothing is happening, ambient filler that fits the moment (before/after
detection, share infected, stats, Remediation bar).

## Strains, unlocks and scenarios (Phase 4)

- **Strains** (`data/strains.js`) differ by base stats, multipliers (`modifiers`) and
  `special` mechanics read by the engine: free starting evolutions (Macro Virus), built-in
  tag bonuses and link weights, passive income (Botnet), built-in clean resistance
  (Rootkit), cheaper or dearer evolutions, **mutation** (Polymorphic: every few days a free
  random evolution, or the loss of one) and **ransom** (Ransomware: the Encrypt button,
  `triggerEncryption()`; encrypted machines are a subset of infected ones that cleaning
  can't touch, only reimaging; you win when every machine is encrypted).
- **Unlocks**: each strain names the one you must beat (`unlockedBy`). Wins are saved in
  the profile (`beaten`). The setup screen's playtest link (or `?unlock=all`) unlocks
  everything for one visit without saving (so does the debug panel).
- **Scenarios** (`data/scenarios.js`) are applied when the world is built:
  `createWorld(data, scenarioId)` returns a world whose `data` has the scenario's site and
  balance changes, so the engine reads them like any other data. Extra rules: `merger`
  (a country's regions have no machines until a day, then join with weaker traits),
  `defenseFromStart` (the defender AI runs from day one) and `patchDeadline` (you lose on
  that day). The game keeps one world per scenario (`Game.worldFor`).

## Polish: scoring, screens, sound, debug (Phase 5)

- **Flow**: title screen → setup → game → end screen → setup again or the title. The title
  leads to the stats page (lifetime totals, best ten scores, strain progress) and settings
  (sound, volume, reduce motion, news ticker, starting speed, reset progress).
- **Scoring** (`src/score.js`, knobs in `BALANCE.score` and each difficulty's and
  scenario's `scoreMult`) is computed when the game ends. `main.js` saves a summary of the
  game to the best scores and stats, unless the debug panel was used (`state.cheated`).
- **History** for the timeline graph: every `historyEvery` ticks (and at the end),
  `[tick, healthy, infected, remediated, encrypted, remediation %]`. `src/ui/timeline.js`
  turns it into shares of the network (`timelineSeries`, pure) and marks detection, the IR
  firm, the merger and Encrypt from `state.log`.
- **Sound** follows the same events the ticker and toasts use (drained each frame), plus
  bubble pops and menu clicks. Each sound has a minimum gap so bursts don't pile up.
- **Animations**: map shockwaves when a region falls, is cleaned or is patient zero; the
  score counting up and the graph drawing in; the glitching logo; the points bump; the
  detection alarm round the screen edge. Reduce motion (or the system setting) turns the
  decorative ones off.
- **Debug panel** (`src/ui/debug.js`): live numbers and cheats that call the same sim
  functions as the game (`advance`, `detectNow`, `endNow`, `applyResponse`).

## Data schemas

Every file in `data/` starts with a commented schema. In short:

| File | What it holds | Key fields |
|---|---|---|
| `balance.js` | global numbers | `ticksPerSecond`, `statMax`, `spread.{power, within, between, traitWeights}`, `linkKinds.{kind}.weight`, `bubbles.*`, `evolve.{costGrowth, refundRate}`, `caps`, `detection.*`, `remediation.*`, `defense.*`, `score.*`, `historyEvery` |
| `strains.js` | playable strains | `id, name, tagline, description, unlockedBy, base.{spread, noise, impact}, modifiers.{withinSite, betweenSites, bubbleChance, bubbleValue, evolveCost, remediation, detection}, special.{startsWith, tagSpread, linkWeights, pointsPerDay, cleanResist, statMult, evolutionCost, mutation, ransom}` |
| `geo.js` | generated geography | `GEO_REGIONS {id, name, country, kind, anchor, neighbors, rings}`, `LAKES`, `METROS [name, regionId, lon, lat, pop]` |
| `sites.js` | region flavour | `TRAIT_BASE`, `TAGS.{tag}.{label, traits}`, `REGIONS.{id}.{tags, blurb}`, `FACILITIES` (air-gapped extras) |
| `links.js` | network links | `from, to, kind (wan/vpn/cloud/email/airgap; borders are added automatically), requires (evolution id or null)` |
| `evolutions.js` | the three trees (24 nodes) | `id, branch, name, description, cost, prereqs[], effects.{spread, noise, impact, tagSpread, remediationResist, cleanResist, reinfect, pointsPerDay, jump}, pos.{col, row}` |
| `difficulties.js` | difficulty settings | `detection, remediation, aiInterval, funding, smarts, scoreMult` multipliers |
| `responses.js` | SecOps responses | `id, name, description, headline, scope (global/site), maxUses, target, minAlert, cost, weight, triggers, duration, counteredBy[], effects.{closesLinks, blocks, traits, spread, remediation, cleanNow}` |
| `scenarios.js` | scenarios | `id, name, tagline, description, sites.{devices, traits}, balance (deep-merged overrides), merger.{atDay, country, traits}, defenseFromStart, patchDeadline.{atDay}, scoreMult` |
| `headlines.js` | news ticker | `id, text ({site}, {strain}, {company}, {day}), when.{event, id, gained, site, tag, strain, scenario, detected, minShare, maxShare, minStat, minRemediation}, once, weight` |
| `world.js` | map settings | `projection.{lon0, lat0, lat1, lat2}`, `insets`, `padding`, `focus` |

`npm test` runs `src/validate.js` over all of it: unique ids, values in range, every
reference resolving (link sites, link `requires`, prerequisites, `unlockedBy`), no
prerequisite cycles, every connected site reachable without evolutions, air-gapped
sites reachable only over airgap links, and every response and headline well-formed
(known evolutions, link kinds, events, tags and placeholders).

## Build and deploy

`build.mjs` bundles `src/main.js` (with all of `data/`) with esbuild (ES2022, ESM,
minified), inlines it and the CSS into `dev.html`'s markup, adds a "generated, do not
edit" comment and a CSP with the sha256 of each inline script, and writes `index.html`.
It fails if `dev.html` still references any local file. The Tests workflow runs lint,
build and tests on every push and pull request; Deploy publishes only `index.html` to
GitHub Pages after Tests succeeds on `main`.
